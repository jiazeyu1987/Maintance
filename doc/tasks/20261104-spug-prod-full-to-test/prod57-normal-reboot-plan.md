# 正式服正常重启方案（待授权、待前置通过）

## 目的与范围
处理172.30.30.57上长期CIFS/SMB重连等待、1973个旧探测D状态进程、Docker线程等待与后端健康不可达的现场。结合这些证据，建议安排一次受控的正常操作系统重启；这不是已证实唯一可行解，也不能保证修复NAS服务端或网络问题。

仅目标正式服172.30.30.57，PROD；不重启172.30.30.58、.59或NAS。整机重启会中断该主机所有业务，包括数据库、对象存储及其它已部署应用，影响范围大于主程序。用户确认旧探测电脑已关停且当前无并行维护，但尚未明确授权整机重启。

## 事前必查与阻塞条件
1. 用户明确同意正式服PROD正常重启及整机业务中断，并确认当前维护窗口。
2. 具备能在SSH失效时观察启动/关机状态的虚拟机或物理机控制台；缺失则不远程触发。
3. NAS服务/网络可用性有独立证据；仅TCP445可达不算SMB恢复。若NAS本身仍故障，先恢复NAS服务/网络，不盲目重启业务机。
4. 只读记录主机身份、boot_id、NAS挂载/fstab摘要、容器/服务清单和可取得的启动/健康状态、未解决备份/恢复/发布操作与锁。已经超时的观察保留为未知；不得为凑全证据反复发起NAS statfs。
5. 不存在正在进行的数据备份、恢复或发布写入；未知操作必须先确认归属，不能假定超时即退出。数据库采用正常关机流程，不强制杀进程。

## 经授权后的执行边界
前置全部通过后，仅请求操作系统正常重启并通过控制台观察。若正常关机被CIFS/Docker拖住，停止自动执行并报告实际状态；本授权不包含强制reboot、SysRq、断电、重置虚拟机、杀死业务进程或强制卸载。

不删除NAS数据、不更改fstab或挂载定义、不改镜像/应用版本、不执行全局Docker清理、不覆盖数据库。启动过程中系统自动重建既有挂载属于正常重启流程，不人工移除受保护NAS挂载。

## 重启后验收与后续原目标
核boot_id变化、SSH稳定、D状态/SMB等待与内存压力、NAS原挂载和有界可读性、真实backend/Redis/MySQL/MinIO状态、backend health=UP、frontend HTTP200及实际页面。重启不等于修复成功，任一必需项失败则保留阻塞。

全部来源和目标准入通过后，才继续原目标：在Spug创建唯一新的正式FULL，验证完整包，再在Spug将该新包恢复到测试服，验证源恢复运行及测试服数据/页面。不能用本次重启或旧备份代替完成原目标。

## 授权规则来源
当前任务AGENTS.md要求正式环境操作有明确授权；现存权威docs/server-access.md规定“正式服务器和审查服务器按生产等级处理，发布或重启必须显式确认 PROD”。本方案只供确认范围，尚未执行重启。
