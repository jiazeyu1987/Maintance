# 在 Spug 选择备份包和恢复服务器

“未登记目标”表示该主机还没有可用的恢复实例登记。Hosts 中有服务器，只代表主机已登记；覆盖恢复还需要绑定该实例的数据库、附件存储、Redis、控制服务和资源归属。这个提示本身不表示备份包损坏。

## 如何恢复到指定服务器

1. 打开“备份与恢复”→“全部包清单”，在所需备份行点击“恢复”；也可从“恢复”页选择来源和备份包。
2. 核对“服务器地址”：这里是备份来源。例如正式服 172.30.30.57。再核对包的备份时间、版本和编号。
3. 选择执行模式和“覆盖现有程序”。安全模式会执行完整校验，不能用快速模式结果代替安全模式完整一致性验收。
4. 在“恢复服务器地址”选择本次真正写入的服务器。例如测试服 172.30.30.58。来源和目标是两个独立选项。
5. 阅读确认页并核对包与目标后确认覆盖。该操作会替换目标实例现有数据库记录、附件和 Redis 数据。
6. 在“执行进度”跟踪同一操作编号，等待真实成功终态，并检查数据库、附件、Redis 的校验回执及目标程序登录、真实页面。受理或 HTTP202 仅表示已提交。

## 以后正式服的新备份

符合合同的新备份和祖先链会被来源目录自动发现，无需逐包登记。已登记目标且当前准入通过时，可以在 Spug 中选择。主机登记不保证任意版本、任意备份均可恢复；包完整性、程序版本、实例身份、存储归属、资源容量、控制服务和任务占用会逐次核对。

## 无可用目标或恢复失败

先记录原操作编号和错误码，核对该来源允许的目标、控制服务、原路径挂载和当前恢复任务占用。目标清理或导入后失败时，业务服务应保持停止，按保留失败记录的正式恢复机制处理。不要重复点击、手工删锁/claim、修改失败为成功，或直接启动未完成恢复的程序。

本轮失败、授权、修复、原始终态和新旧操作关联统一保留在同目录 execution-log.md 及 restore-attempt-*；本操作说明不代替实际执行证据。
