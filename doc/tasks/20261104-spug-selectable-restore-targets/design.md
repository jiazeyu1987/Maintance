# 指定服务器恢复设计与待核前提

## 用户可观察结果
在 Spug 全部包清单点击数据备份包的恢复，固定该包及来源，在弹框选择测试服务器 .58、审查服务器 .59 或正式服务器 .57，并选择覆盖现有实例或恢复到独立实例。预检后展示具体将写入的应用、数据库、附件和 Redis 范围；确认内容固定该目标身份。取消或预检失败不产生恢复任务。不得由客户端任意路径、IP 或引用绕过现有执行器。

## 已证实的代码约束
1. 清单入口已有包身份绑定，safe/replace 为默认方式。不能通过改用另一个包、改成快速模式或移除校验掩盖目标缺口。
2. Spug 公开服务器列表和目标映射属于不同数据。当前 .57 safe 的空目标映射有三服地址，但覆盖映射为空。
3. SmallAppBackupUiRequest/v1 精确固定七个字段，使用 targetConfigRef；目标必须同时存在于来源登记、Spug 私密桥路由、目标服务 restoreConfigurations 和具体恢复 owner 配置。单改页面或 overwriteTargetServers 不足以接通执行。
4. 后端 Native.resolve 以来源、目标、恢复点解析不可变配置 Pin；目标配置不能直接复用源配置。保留旧原编号的请求、查询路由和历史身份。
5. recovery_replace.validate/verify_services 目前限定登记的真实容器 ID、镜像、数据库 UUID、服务挂载、Redis 库及独占本地 Docker 数据卷；实际覆盖清空指定业务库、MinIO 物理目录和 Redis DB。不能假设正式主系统符合小程序独立卷合同。
6. 后端现有 HTTP 仅有 /operations 和 /selections，没有在页面中按服务器准备或登记主实例目标的接口。用户需要的自助选择必须与正式目标解析/登记能力一起交付。

## 实现方向
保留现有备份包、原编号、进度及确认合同。以统一的目标服务器资料和真实实例资源定义作为目标解析依据，支持每次由页面选择服务器及恢复方式；后台据实解析该服务器上的目标，不再要求每次人工编辑来源映射。只读预检与最终执行分离，执行前再次核对目标身份、资源占用和所选备份链，绑定后的目标变化必须拒绝，不自动改到其他实例。

目标资料必须来自三服当前运行定义和现有执行服务。预登记层只负责基础设施与资源范围，用户每次操作不需要改后台文件；按服务器解析时不能把已使用的独立目标转为主程序覆盖目标。

### 只读核查后的收敛
现有UI已支持按次选择已登记的服务器；三台固定主实例可以一次正式配置/登记，不必为了补恢复目标而另造动态登记页面。当前主要缺口是恢复owner和真实资源合同：.57/.59 safe执行器均无restoreConfigurations，.58/.59主实例使用named volume，.57使用bind。正式服backend反复重启、负载异常，未完成运行态核验。具体证据和未验证边界见assessment.md；不通过放宽volume条件或复制fresh引用接入正式服。

将现有替换引擎的存储检查提取为独立存储边界模块，属于小范围重构；依AGENTS的Refactor Workflow Policy采用Subagent-Driven Development。子任务负责真实路径/挂载/资源边界校验和失败优先测试，主任务负责恢复配置/登记接入和整体回归；模块所有权分离，不操作服务器。

存储扩展必须显式版本化；既有v1仍只接受独立local volume，新v2必须登记每个写存储的目录身份、设备、inode、挂载类型和保护范围，拒绝符号链接、祖先/后代重叠、其他RW消费者和NAS。所有破坏性操作之前重复检查，失败保留，不自动选择其他路径。

## BDD 场景
- Given 正式服数据备份包，When 依次选择 .58/.59/.57，Then 所选包和来源保持不变，目标指向对应服务器真实实例。
- Given 选择覆盖模式，When 目标核验通过并打开确认，Then 展示目标服务器、实例、数据范围并要求明确覆盖确认。
- Given 选择独立恢复，When 核对目标，Then 必须为空且与现有源及目标主程序存储隔离，不能复用已使用目标。
- Given 目标不具备恢复条件、身份不一致或后端服务未支持，When 预检，Then 显示具体原因，取消可安全退出，不提交任务。
- Given 预检后目标发生变化，When 最终提交，Then 后端拒绝而不重新解析到其他目标。
- Given 操作已经受理，When 页面刷新或重复查询，Then 仍绑定原包、原目标和原编号，不产生另一次恢复。

## 所需只读核查
在用户明确允许的范围内，核三服主实例的真实容器角色/ID、数据库及 UUID、存储类型和挂载归属、Redis 使用范围、既有控制服务/引擎版本与配置引用、NAS 归档访问路径、任务锁和恢复占用。只输出必要非凭据摘要，不检查或修改业务数据，不触发恢复、停服或写配置。

这些事实决定是直接复用现有恢复 owner 还是需要正式扩展主系统的存储与锁合同；未核实前不能把一个 fresh 配置转换成主系统 replacement，也不能宣称三服覆盖可用。
