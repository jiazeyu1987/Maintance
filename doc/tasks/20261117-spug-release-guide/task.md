## 经验门禁
- 发布操作前必须阅读 `docs/release-backup-restore.md`；服务器访问与登录分别遵循 `docs/server-access.md` 和 `docs/login-access.md`。
- 完整发布使用同一 releaseTag 的 `build-release -> publish-test -> mark-tested -> promote-prod -> promote-backup`；仅测试服发布止于 `build-release -> publish-test` 与真实运行态及页面验收。
- 实际构建发布必须新建专用临时 worktree 并固定已提交目标；本次仅做文档核对，不创建发布环境。
- 成功需同时核 operation、manifest、远端 IMAGE_TAG、前后端镜像、后端 health 与前端 HTTP。
- 未获明确发布授权，不操作服务器；本次咨询不等同发布授权。
- 中文读写显式使用 UTF-8；日志不得记录明文凭据。
- Spug 构建只读所选完整 Git 提交，使用专用干净 worktree；构建、封包和原包摘要保持不变。
- 以实例显式策略决定是否需要隔离演练：`direct-three-server-v1` 允许测试通过后直接晋级；未配置时保留原演练门禁。
- 正式部署技术检查通过后仍保持维护；真实业务验收后执行 `accept-prod` 才开放。审查服需正式同包已验收开放。
- `productionRecovery=external` 仅记录独立恢复责任确认，不能解释为 Spug 已验证外部备份；不能承诺每次正式发布都会全量备份。
- 活动操作及未解决失败阻止重复提交；失败证据必须保留，不通过改历史或清锁绕过。
