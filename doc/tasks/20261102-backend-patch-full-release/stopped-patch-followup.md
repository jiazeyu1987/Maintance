# 全量承接补丁的停服取证与检查点续接

## Current Status
in_progress

## 目标与证据
测试全量JOB-0a72553fa4/OP-17c1c8c02e942b8010dc在完整检查点封存后、程序替换前失败。`observe()`只在Running时计算JAR SHA，停止的补丁容器jar_sha=None却继续比较标签。原容器及程序未替换；不修改包、数据库、原失败记录或正常运行数据库边界。

## 设计约束检查
- 是否引入fallback/降级/吞异常：否；停止状态读取经过归属验证的只读挂载，任何字节/容器/挂载不符继续阻断。
- 是否从根因和长期维护角度解决：是；发布观察器覆盖正常停服状态，既有显式续接入口支持完整检查点后、零迁移及未切程序的边界。
- 是否存在临时补丁或绕过：否；实现、测试、空闲安装后仍通过Spug显式技术续接。

## BDD与里程碑
1. Given已验收的只读补丁挂载，When后端停止，Then读取真实文件SHA并保持原指纹；未知挂载、可写、链接、文件改变或容器身份漂移都拒绝。
2. Given原任务失败且worker停止、同包所有字节及完整检查点真实匹配、原容器/配置/JAR/schema/ledger保持、无本tag迁移/待执行迁移及活动写者，When显式续接，Then复用原检查点仅执行程序切换和验收；不重复备份、执行迁移、恢复数据库或伪造原成功。
3. Given检查点缺损、原容器漂移或计划有APPLY，Then首个程序写入前失败关闭。
