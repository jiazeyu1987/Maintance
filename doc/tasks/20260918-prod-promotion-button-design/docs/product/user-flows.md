# 已测试发布包发布正式服用户流程

## Purpose and Scope

定义发布操作者如何从已经测试验收的程序发布工作流，通过一个新的“发布到正式服务器”按钮完成受控正式发布。流程覆盖资格判断、只读预检、确认、执行、监控和失败恢复提示。

## Evidence Reviewed

- 当前运行控制台已有标准程序发布区域和工作流选择器。
- 候选实现已有 `publish-test`、`test-acceptance`、`production-authorization`、`promote-prod` API。
- 现有发布脚本已具备正式确认、测试 operation 证据和 production dry-run 证据门禁。

## Primary User Flows

### UF-PROD-001 正常发布

1. 操作者登录运行控制台并进入“标准程序发布”。
2. 页面加载服务端工作流列表，默认选择最近更新且可查看的工作流。
3. 操作者选择状态为 `TESTED` 的工作流。
4. 页面展示 releaseTag、包摘要、manifest 摘要、来源提交、测试 operation 和验收信息。
5. 操作者点击“发布到正式服务器”。
6. 页面调用服务端只读 production preview；按钮进入“正在检查”，不能重复提交。
7. 服务端返回全部检查项为 PASS、短时 preview ID、目标正式服务器和当前正式版本。
8. 页面打开确认对话框，展示目标、版本差异、变更摘要、迁移摘要、恢复准备和风险提示。
9. 操作者填写发布原因并精确输入 `PROD`。
10. 页面先申请一次性授权，再用 preview ID、授权 ID、状态版本和幂等键提交正式发布。
11. 页面进入监控视图，显示 operation ID、当前步骤、持续时间、最后进展和日志入口。
12. 服务端完成正式发布和最终证据核验后，工作流显示 `COMPLETED`，页面显示正式服当前版本与同一 releaseTag。

### UF-PROD-002 查看发布结果

1. 观察者重新打开或刷新页面。
2. 页面从服务端读取工作流和 operation，而不是依赖浏览器内存。
3. 页面恢复当前阶段和历史证据。
4. 若已完成，显示最终验收项；若处于恢复态，显示阻断原因和恢复负责人入口。

## Alternate Flows

### AF-PROD-001 按钮不可用

- 非 `TESTED`、无权限、存在活动生产 operation 或工作流存在 errorCode 时，按钮保持可见但禁用。
- 按钮附近显示最优先的服务端阻断原因和下一步，例如“需要先完成测试验收”或“生产环境存在未完成恢复任务”。

### AF-PROD-002 预检状态过期

- 操作者打开确认框后正式服状态发生变化，提交时服务端返回 `PRODUCTION_PREVIEW_STALE`。
- 页面关闭最终确认态，保留用户填写的非敏感原因，要求重新执行只读预检。

### AF-PROD-003 重复点击或网络重试

- 页面禁用按钮；即使请求被重发，服务端按 idempotency key 和工作流/环境活动锁返回同一 operation。
- 页面转入既有 operation 监控，不产生第二次写入。

### AF-PROD-004 正式服已是目标版本

- 服务端仍执行完整只读证据比对。
- 全部一致时返回幂等完成结果；存在 `.env`、镜像、health 或 operation 任何漂移时返回 blocker，不把 HTTP 200 当作成功。

## Error Flows

### EF-PROD-001 预检失败且零写入

页面展示逐项 blockers；工作流保持 `TESTED`，不创建生产 operation、不消费授权、不取得或保留生产写锁。

### EF-PROD-002 确认失败

输入不是精确 `PROD`、授权过期、权限不足或绑定不一致时，服务端拒绝；页面显示错误，不进行远端写入。

### EF-PROD-003 派发后失败或结果未知

页面显示 `RECOVERY_REQUIRED`，明确“禁止再次发布”。系统保留生产隔离和证据，提供查看 operation、现场检查清单及恢复入口，但不自动回滚业务数据。

### EF-PROD-004 最终验收不一致

即使脚本退出码为 0，只要 `.env`、实际镜像、health、HTTP、release-info 或锁状态不一致，页面不得显示完成，工作流进入恢复态。

## Out-of-Scope Flows

- 从源码重新构建或修改包后直接发布正式服。
- 未经测试验收直接正式发布。
- 正式发布后自动发布审查服。
- 在此按钮内执行数据库人工修复、业务数据回滚或恢复整库。
- 浏览器输入任意 SSH 主机、远端目录、脚本或凭据。

## Open Questions

- 若未来启用双人审批，授权签发和最终执行需拆成两个登录身份；首版不包含该流程。
