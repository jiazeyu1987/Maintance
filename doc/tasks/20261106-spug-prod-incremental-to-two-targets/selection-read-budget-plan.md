# Spug 恢复目标刷新根因修复

## Current Status

in_progress。实现及必要复核已通过：最终父Python114项、UI92项、实际容器Python3.9共39项均PASS；真实候选对来源57到目标58只读19.143秒通过。准备独立实现提交及已提交资源构建，尚未安装或完成真实UI/恢复验收。这是原完整目标中的实际产品缺陷，不开启其它任务。r10原session42144中止exit1及各失败原件保持；阶段B现场验收必须绑定实际新资源代次。

## 已证实根因

1. 实际选定来源 57、目标 58 时，HttpBridge.selections 仍遍历目标配置的三个来源，向相同来源目录重复请求三次。真实分别耗时 6.704、6.835、6.769 秒，尚未查询目标就超过浏览器 20 秒截止。
2. 随后的目标准入 GET 在桥接层 10 秒超时。独立只读诊断只扩大本次观测等待，实际目标 11.251 秒返回，三个来源均有该目标；这只证明目标读调用，不能冒称 UI 或恢复通过。不得通过关闭准入或直接启用按钮处理。
3. 容器 Python3.9 的 socket.timeout 被归入 BRIDGE_IO_FAILED；要以运行时类型修复诊断，保留安全错误码且不输出原异常中的秘密。

证据：spug-selection-timing-r1/r2.json、spug-target-timing-r1.json 与私密原请求/程序/输出。

## 正式方案及里程碑

- 已审阅预算：来源读取20秒、目标准入25秒、单次 selections 共享50秒、页面 GET /selections 60秒。仅该只读路径使用严格 headers/body 截止，普通操作与自动计划原预算保持。固定 origin/凭据、禁重定向、响应大小上限和安全错误合同不变；系统 DNS 解析不能声称具备强制总时间上界。
- 对明确选定来源的目标查询，只读取该来源的目录，并与该目标新鲜准入合并；未选来源的完整目录仍保持全量覆盖，备份点资格只取来源。
- 为来源目录和目标准入建立明确、有限且由内向外包络的读取预算；既有普通操作查询及备份派发预算不改变。不缓存旧准入、不自动重试、不以单纯扩大页面等待掩盖重复来源请求。
- 保留真实错误原因至页面，并明确识别 Python3.9 socket.timeout。
- BDD / RED / GREEN / 受影响回归通过后独立提交，按正式资源构建/安装流程处理这次产品改动。当前 A/c1 记录只作为真实历史，不能把新代码记作旧安装；新运行验证按实际安装代次绑定。
- 重新从真实页面验证最新点三服目标，再完成全目录覆盖、新自动增量及真实恢复；全部完整目标仍 in_progress。

## BDD 与预期验证

- Given 目标登记包含多个来源且当前选择来源 A，When 刷新 A 到目标 T，Then 仅查询 A 的来源目录与 T 的当前准入，来源 B 离线不影响 A，T 离线仍明确拒绝。
- Given 未指定来源的完整目录读取，When 获取候选，Then 所有登记来源仍被查询，不能遗漏。
- Given 目标准入耗时超过原 10 秒但在正式预算内，When 真实本机 HTTP 调用和页面请求，Then 完整响应可返回；超出预算时显示超时并禁用提交。
- Given Python3.9 socket.timeout 或其 URLError 包装，When 桥接报错，Then 返回 BRIDGE_TIMEOUT，不泄露连接串或凭据。

## 经验门禁

- Trigger：真实目标刷新超时；Preflight check：先实际分段计时和当前源代码，不凭 UI 通用错误推测。
- Blocker：未能证明来源/目标绑定、预算无界、未保留源资格或实际新构建来源不明。
- Verification：先失败测试、再修复和回归；实际 Python3.9、原生 HTTP、真实 UI 分层证据。
- Forbidden action：不删除失败、不绕过准入、不扩大到恢复写入、不复用旧代码 SHA 冒充新部署、不循环重试。
- Evidence：本计划、实际时序记录、RED/GREEN/回归及新资源构建/安装记录。
