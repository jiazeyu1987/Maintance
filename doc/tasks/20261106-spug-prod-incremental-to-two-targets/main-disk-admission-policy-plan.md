## 设计约束检查

运行准入模式独立登记在 owner 的 `targetResourceAdmissionPolicies[targetRef]`，采用完整 RestoreResourceBudget/v2；所有原内存/路径预算值与该目标原 v1 预算逐值一致，仅增加模式和版本。物理 target、baselineTargetPin、原 epoch 与历史配置完全保留；不能为了改变运行预留而重写业务基线。运行时统一 configured_budget 选择策略；显式映射错误或缺本目标时拒绝，旧无此字段配置继续按明确的 v1 合同执行。

- 是否引入 fallback/降级/吞异常：否。采用显式磁盘准入模式，不因严格预检失败而自动降级，不吞磁盘写入错误。
- 是否从根因和长期维护角度解决：是。统一配置和准入规则，避免只修改安装器而运行时仍要求 178 GiB。
- 是否存在临时补丁或绕过：否。不直接更改已有包或伪造空间值，不把 178 GiB 改成另一个无依据常量。

## 经验门禁

- Trigger：备份恢复资源准入、三服控制组件安装；Preflight check：先核对正式配置契约、各路径所在设备及原服务/原清单身份；Blocker：配置策略未贯通或真实写入失败；Verification：RED -> GREEN -> REGRESSION，安装前固定提交包和原服务证据；Forbidden action：删除旧备份凑空间、改变公司 NAS 挂载、吞异常或伪造成功；Evidence：本任务 execution-log.md、独立测试报告和安装回执。
- Trigger：Windows/SSH 中文及多行载荷；Preflight check：显式 UTF-8、固定解释器、参数化载体；Blocker：编码或退出码不可信；Verification：读取回写字节及原生退出码；Forbidden action：默认编码与敏感日志提交；Evidence：仅脱敏摘要进入仓库。

## BDD 场景

- Given 用户明确选择按实际可用空间运行，且现有空闲小于各最大预算之和；When 目标准备保全与恢复；Then 不因固定最大预算相加而阻断，继续其他准入检查。
- Given 严格预留模式；When 空闲不足预算；Then 继续明确阻断，保持既有严格行为。
- Given 按实际可用空间运行且写入实际失败；When 保存保全资料或恢复数据；Then 操作失败并保留可追踪原因，禁止报告成功或继续破坏性阶段。
- Given 未知、缺失或错误策略配置；When 加载目标配置；Then 按明确版本契约处理，禁止静默改模式。
