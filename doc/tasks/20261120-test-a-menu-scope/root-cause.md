# 测试A菜单越出套餐范围

## 已证实事实
- 环境：测试服172.30.30.58，当前发布版本2026-11-20-14-42-40；租户测试A（169），专属套餐114“瑛泰套餐”，无其他租户共用。
- SRM（991000）、CRM系统（2397）、AI大模型（2758）及全部有效后代共218个菜单ID，均不在该套餐和目标租户有效角色菜单绑定中。平台配置界面也显示未勾选。
- Playwright新会话登录目标账号，用户910251只有tenant_admin角色，仍显示三个模块；登录权限响应含对应子树60个导航菜单。
- 本地业务数据库未运行，未验证本地测试1实时配置；测试服务器的测试1不是本地测试1，不能替代。

## 根因与修复要求
应用源码基线152a084c3ebc8eefcddf300f66384e1117b297b9。
后端yudao-module-system/src/main/java/cn/iocoder/yudao/module/system/service/permission/PermissionServiceImpl.java第331—347行，getRoleMenuListByRoleId读取全局菜单并为tenant_admin自动追加业务菜单，没有按租户套餐约束返回集合。TenantAdminBusinessPolicy业务模块包含srm、crm、ai。这解释了套餐、角色均未授权但新会话仍返回菜单的现象。

同文件第179—191行hasAnyPermission存在对应业务权限自动通过分支；需要一起审查和修复权限边界，不能仅在导航隐藏三个名称。此处接口风险由代码确认，未执行越权业务请求。MenuServiceImpl.getMenuListByTenant已有tenantService.handleTenantMenu过滤方式，可作为现有正式边界实现的参考；具体方案由应用任务结合平台租户例外、临时授权和ERP显式授权设计。

不应重新运行旧菜单SQL、全局设置visible=false、删除功能或移除目标账号管理员角色。上述做法不能解决根因，且可能影响其他租户或其他管理功能。

## 应用任务BDD与验收
1. Given测试A套餐不含三个模块且用户仅tenant_admin，When新登录，Then导航及权限响应不返回这些模块和后代，直接路由不能获得相应页面权限。
2. Given套餐不含对应业务权限，When该租户管理员访问相关受控接口，Then权限拒绝；需在获授权测试数据与安全操作范围内验证，不得用实际越权写入验证。
3. Given套餐包含正常业务模块，When租户管理员使用已授予功能，Then原功能可用；保留ERP必须显式授权规则与其他角色边界。
4. Given其他租户/平台管理身份，When检查其既有授权，Then不受测试A收敛影响；若调整平台例外必须有明确契约。
5. 应用仓先失败测试RED，再最小实现GREEN与回归；维护任务在对应已提交版本上按测试服发布流程构建部署，最后真实登录测试A验证菜单、权限、版本一致性。
