状态：completed（发布入口、真实构建及测试服部署验收；不代表三服业务验收完成）。

目标：在 Spug 发布中心应用选择中加入分贝通，独立状态和执行器。构建本地 student-collaboration-kit 的明确源码快照，原包按测试、正式、审查服推进，记录部署与人工验收。正式发布前执行独立数据副本演练，初次未部署时演练空数据安装。

源码尚无 Git 仓库，不显示虚构 Git 提交。快照只包含 server.js、package 文件和 backend/src、frontend/src；排除 .env、runtime-data、凭据、依赖缓存及历史实验。构建含 Node 运行时的单镜像，三服环境配置和数据不随程序包复制。现有 IntRuoyi 是外部授权依赖，不修改其代码、容器或租户。

实现：快照/完整包与摘要 → 发布执行器、同包和顺序门禁 → 独立应用页面与注册 → 本地真实构建、失败分支测试、Spug 按钮检查。不会把端口健康冒充业务功能验收，不执行分贝通同步或金蝶写入。用户本次要求增加入口，不默认执行正式三服业务发布。

经验：发布输入固定、远端配置明确、错误原样保留、数据不打进包、共享 Spug 仅更新自己的入口。不加入隐式 fallback。源码快照是一种显式输入模式，不替代 Git 模式或伪造提交记录。需要的运行时缺失时阻止构建；迁移不支持任意新脚本自动执行。

验收范围：包中无本地配置/业务数据；数据目录持久化；重复请求返回原任务；测试验收前不晋级正式；正式验收前不发布审查服；包摘要冲突、未知远端状态、旧包覆盖均阻断；原失败任务和日志保留。
