## 设计约束检查
- 是否引入 fallback/降级/吞异常：否。
- 是否从根因和长期维护角度解决：是，业务维护版本契约，发布统一执行，不硬编码业务值。
- 是否存在临时补丁或绕过：否。

## 经验门禁
- Trigger：发布执行链、封包契约和数据库检查修改。
- Preflight check：先核 worktree、已提交输入、现有执行接口及测试；读取发布和 worktree 对应经验；BDD 先行。
- Blocker：接口未定、RED 无效、真实数据库证据缺失、安装来源不明或活动发布争用。
- Verification：实际构建/远端入口调用链、失败不开放、不可变摘要、无迁移重放、真实 MySQL 与集成回归。
- Forbidden action：不改已执行 SQL、不补假账本、不删除约束绕过、不把缺契约当通过、不混入其他任务改动。
- Evidence：execution-log.md、跨仓交付回执及测试报告；高风险动作前记录 experience-preflight。
