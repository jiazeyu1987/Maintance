# 经验文档写入规范固化

## 任务目标

将已优化的前置经验结构固化为项目级强制写入规范，使后续新增或更新经验文档时统一采用可检索、可执行、可验证、可阻塞的门禁格式。

## 里程碑

- [x] M1：确认上一任务已完成并读取经验索引与适用经验规则。
- [x] M2：在项目级入口固化经验归档位置与标准字段。
- [x] M3：在 `AGENTS.md` 固化后续经验写入强制流程。
- [x] M4：验证关键词可发现、UTF-8 编码与差异范围。
- [x] M5：完成收尾清理并提交本任务文件。

## 预期验证

- `docs/experience-index.md` 明确后续经验必须采用优化后的门禁结构。
- 根目录 `AGENTS.md` 明确经验写入前先定位归宿、优先更新既有文档、同步索引和清单。
- 规范至少覆盖：触发场景、前置检查、阻塞条件、验证证据、禁止做法、问题记录和避免复发。
- `rg` 可通过“经验文档写入规范”“Trigger”“Preflight check”“Blocker”“Verification”“Forbidden action”发现该规则。
- 所有本任务修改文件按 UTF-8 正确读取，`git diff --check` 通过。

## 经验门禁

- 优先更新已有经验文档，不把一次性任务状态写入长期经验。
- 新增经验必须先在 `docs/experience-index.md` 建立可命中的关键词路由。
- 可前置检查的问题必须写成门禁，不只记录事后叙述。
- 门禁条目必须包含触发条件、精确检查、阻塞条件、验证证据和禁止绕过动作。
- 涉及执行流程的门禁必须同步更新对应 checklist。
- 中文文件使用 UTF-8，无明确要求不得改变既有编码。
- 只提交本任务产生的文件，不纳入工作区已有无关改动。

## 设计约束检查

- 是否引入 fallback/降级/吞异常：否。
- 是否从根因和长期维护角度解决：是，通过项目入口和根级规则双重固化，避免只在单次任务中约定。
