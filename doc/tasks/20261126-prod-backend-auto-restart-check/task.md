# 正式服后端自动重启能力核查

## 目标与范围

核对当前正式服后端进程或容器异常退出后是否由正式运行控制机制自动重启。仅执行只读配置、状态和日志核查，不停止进程、不注入故障、不修改服务器或业务数据。

- [x] 记录结论、证据和已知边界。

## 预期验证

明确区分“容器进程崩溃自动拉起”“应用健康失败自动重启”“宿主机/编排器故障恢复”三种能力，并以当前正式服实际配置或运行态证据为准。

## 设计约束检查

- 是否引入 fallback/降级/吞异常：否。
- 是否从根因和长期维护角度解决：是，本任务只核对正式恢复机制，不以人工重启或单次健康检查替代自动恢复配置。
- 是否存在临时补丁或绕过：否。

## 经验门禁

- Trigger：正式服后端自动重启能力、service_recovery、unhealthy、容器 restart policy。
- Preflight check：先读取 server-access、service-recovery 与正式发布运行态门禁；只读核对远端运行控制身份、重启策略、健康检查和最近重启计数。
- Blocker：无法证明正式服实际生效的运行控制配置、只看到镜像标签或单次 health=UP、需要停止/杀进程或写服务器才能确认时，保持结论为未知，不做破坏性验证。
- Verification：记录正式服后端容器/服务实际 restart policy、healthcheck、restart count、控制器归属和配置来源；区分异常退出拉起与健康失败处置。
- Forbidden action：禁止正式服注入崩溃、停止后端、盲目重启、修改 compose/systemd/编排配置、操作业务数据或 /mnt/nas。
- Evidence：本目录 execution-log.md 与只读核查回执。

## 最终结果

只读核查通过：异常退出自动重启已启用（unless-stopped），健康失败/假死恢复未安装启用。当前后端UP；无正式服故障注入、重启或配置写入，无本任务临时worktree/控制台需要清理。详见verification.md。
