## 为什么备份会停服
当前实现选择停写一致性捕获：停止source.writerContainerIds指定的业务写入容器，将MySQL全局read_only及super_read_only设置为ON，验证保护后才采集数据库和附件。这样避免数据库引用、附件内容和增删操作跨越不同时间点；停止业务进程也隔离应用内后台任务写入。

现有实现把数据库导出、语义证据和逐表数据核对置于保护窗口内。采集完成或受控异常处理后，先恢复MinIO等数据服务，再恢复数据库原只读标志，最后恢复业务容器；若数据服务恢复失败，保留业务停止状态。来源恢复必须生成source-restoration.json并通过校验，不能只凭文件导出完成宣告可用。

这属于当前备份流程的实现边界。要缩短停写窗口，需要另行设计并验证数据库与附件的共同快照、写屏障及后续校验边界；仅移除停止或只读步骤会削弱现有一致性保证。本次不修改流程。
