# PRD：DCC 短编码文件名直连识别硬化

## Purpose and Scope

当前 DCC 识别服务在文件名直连阶段使用 `containsIgnoreCase` 识别项目编码，再按“最长且唯一编码”直接命中。这使 `IN`、`OC`、`EC` 等短编码容易在普通文件名中误命中，并跳过后续内容识别。  
本任务的目标是把文件名直连改成“高置信度快捷路径”，仅在证据充分时允许直接回写；证据不足时继续正式识别链路或显式失败。

## Actors

- 文控用户：在 DCC 详情或受控预览里点击“识别基础信息”
- DCC 识别服务：执行文件名直连判定、内容识别调用和回写
- DCC 基础数据维护者：维护 `dcc_project_code` 候选集合，但不在本任务内改码

## Requirements

1. 文件名直连不再以“任意子串包含”作为短编码命中依据。
2. 文件名直连必须引入边界感知匹配，至少区分“完整编码命中”和“只是更长 token 的一部分”。
3. 低置信度短编码不得仅凭文件名直接回写；推荐按“规范化后有效字符长度小于 4”先进入低置信度集合。
4. 长编码的高置信度快捷路径必须保留，不能因为收紧规则把原本稳定的长编码识别一起打掉。
5. 低置信度场景应继续现有正式识别链路；如果内容识别运行时不可用，必须显式失败，不能误回写。
6. 回归测试必须覆盖误命中、长编码保留、同长度歧义和“继续内容识别”四类路径。

## BDD Scenarios

- `BDD: 短编码嵌入普通长 token 时不得直连 -> Given 启用项目编码中存在 IN / When 文件名是 INT-变更记录.pdf / Then 识别服务不得把 IN 当作项目编码直接写回。`
- `BDD: 两位短编码即使单独成段也按低置信度处理 -> Given 启用项目编码中存在 EC / When 文件名是 EC-现场记录.pdf / Then 识别服务不得仅凭文件名完成直连，而应继续正式识别链路。`
- `BDD: 长编码边界清晰时仍保留快捷路径 -> Given 启用项目编码中存在 RE-STM-MM-017-04 / When 文件名包含 RE-STM-MM-017-04（A0）趋势图.pdf / Then 识别服务仍可直接命中该编码并跳过内容读取。`
- `BDD: 同长度多命中时不得强行直连 -> Given 文件名中有多个边界有效且同长度的候选编码 / When 服务评估文件名 / Then 不得直接写回其中任意一个。`

## Acceptance Criteria

- 新增单测能稳定复现当前短编码误命中风险，并在实现后通过。
- 实现后，短编码不再因为普通文件名子串而直接回写。
- 长编码唯一直连能力保持可用，相关既有测试或回归样例通过。
- 低置信度路径在内容识别不可用时表现为明确失败，而不是错误成功。

## Open Questions

- 低置信度阈值是否固定为“规范化长度 < 4”，还是需要结合当前启用编码长度分布再冻结。
- 是否需要把边界规则抽成独立 helper，以便后续项目名称直连或别的识别链路复用。
- 与第二任务联动时，最终测试服联调是使用 API 样本还是 Playwright 前端路径作为主验收口径。
