# 两套备份 / 恢复方案

| 方案 | 引擎包 | NAS 内新归档目录 | 行为 |
| --- | --- | --- | --- |
| 完整核验版 | `backup-restore-standard.tgz` | `archives/prod-standard-<操作摘要>/` | 保留 2026-10-21 已成功演练版本的采集、内容核验、独立 SMB 读回和恢复核验 |
| 轻量版 | `backup-restore-lightweight.tgz` | `archives/prod-lightweight-<操作摘要>/` | 取消文件、数据库、业务一致性及环境预检查；不保证恢复结果准确 |

完整核验也不等于绝对无故障保证。两套保留真实读写失败处理及源服务启动收尾。轻量版不再预先核实源、目标身份或环境隔离。
全量和增量都按所选引擎的目录前缀归档；恢复使用选定的备份点，不产生新备份包。

轻量版的备份、增量和恢复主路径不比较文件内容摘要、预期大小、复制前后状态或最终文件清单，
不做载荷独立回读核验，也不在入口扫描引擎源码摘要。必要的归档记录仍会读取解析。
增量通过文件大小和时间信息识别变化；对象清单信息不变时复用父备份，不再下载内容确认。
文件信息不变而内容改变时可能漏备；损坏的缓存或归档也可能直接传递到恢复目标。
保留执行所需的格式解析、父链顺序读取、路径定位、真实进程退出与读写错误处理，
不把运行失败伪装成成功。gzip/数据库/镜像工具自身的解码或导入错误仍会报错。
归档索引需要的摘要字段、内容标识仍会生成；这不代表执行了比对核验，也不代表取消了文件遍历或复制。
本地打包时仍记录源码摘要，并检查完整核验版原包未变；这些不是轻量版运行期扫描。

## 本地生成

```powershell
python ops/backup_engine/build_variants.py --output-directory output/backup-restore-variants-20261022-r4
```

输出目录必须不存在，脚本不会覆盖已有包。`variants.json` 和各包 `package.json` 记录方案与实际内容摘要。
完整核验版取自同目录 `baselines/backup-restore-standard-20261021.tgz`：
原始引擎提交 `6b39ef658008709b8b909dba4e16f890ad1d913c`，原始包内容摘要
`eb8b63dd5813085228c9d16f06087049810f1e226ef878c3c1d04bdc98bdfd19`。
该原包原样保留。新标准包除归档路径前缀外，应用经过验证的修复：Redis 密码 pin、同库启动 DDL 解析、按请求绑定全量/增量父点、排除已占用恢复目标，以及备份恢复阶段计时。修复集中在 `standard_fixes.py` 和 `standard_timing.py`；补丁上下文变化立即失败，计时包装必须保持原语句 AST 一致。标准包继续启用内容与文件核验。
轻量版明确读取当前工作区允许清单内源码，不冒充干净 Git 发布版本。

## 安装与入口

两包分别解压到不同引擎目录，例如 `engine-standard/`、`engine-lightweight/`。
每套的备份入口为 `repository_entry.py`，恢复入口为 `recovery_entry.py`，
控制入口为 `control_entry.py`；参数与原入口一致。
各套配置的采集命令、恢复模块目录和工具引用必须指向同套引擎，不能只换入口而继续调用另一套采集器。
保留三服各自的来源和仓库配置。切换方案先建立新的 FULL 链，不用另一套的增量链作新链起点。
已有无方案前缀的历史包保持原路径，不重命名。

本次仅生成本地代码包，未更改 Spug、NAS 或三服安装。NAS 上的 `standard`/`lightweight`
目录名在安装并使用对应新引擎后生效。外层人工打包或上传目录也应沿用对应方案名，
本脚本不修改外部上传工具的 `backup.tar` 命名。

## 轻量版本次取消的六类检查

1. 备份数据库的全库、受影响行和表结构比较扫描；只读取导出所需的数据库创建参数。
2. 恢复后的数据库表结构、行数及数据比较。
3. 附件引用、业务不变量及业务一致性比较。
4. Redis 恢复前后的内容、键数及过期时间读回比较。
5. S3 逐对象内容摘要、预期大小、元数据比较及上传后下载核对。
6. 备份链一致性、配置与环境身份、源目标隔离、服务就绪和启动健康预检查。

轻量版结果明确记录 NOT_PERFORMED，不把跳过核验记录成核验通过。
服务启动命令成功不证明业务就绪；VERIFY 动作也只返回未执行核验。
实际文件枚举、增量变化识别、数据传输、归档索引生成和数据库导入仍需要执行，
它们是备份恢复工作本身。工具自身的格式解码、协议与导入错误仍会直接报错。
以上属于本地实现，未在服务器安装，也未通过本轮真实备份恢复演练。

## 后续逐文件检查删减与逻辑对照

轻量版不再对每个载荷执行额外的类型、硬链接、设备身份检查或复制前的父路径磁盘检查，
也不再重复验证全套库存元数据。增量使用原本读取的一次文件属性，避免第二次 stat。
临时目录清理由系统目录删除完成，不再先收集逐文件身份、再比对身份后删除。
仍保留任务根目录约束、路径字符串防越界、真实读写错误，以及索引格式所需的摘要生成；
这些不执行载荷内容比对。遍历、复制和增量判断本身仍逐文件执行。

对照完整版后修复：备份入口返回任务目录；恢复数据库前停止目标应用写入；
恢复物理 MinIO 文件前停止目标 MinIO，完整链应用完后再启动；
恢复成功后清理 full.sql、full.private.gz、incremental.private.gz 等实际临时输出。
停止或复制失败立即报错，不继续启动目标应用。
本地真实文件对照覆盖 FULL→I1→I2，包含新增、修改、删除、文件/目录互换，
两套得到相同内容。此对照不代表数据库、MinIO 服务或完整服务器演练已通过。
