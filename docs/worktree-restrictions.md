# 维护仓构建与 Worktree 限制

本文适用于本维护仓资源包构建；主程序前后端的端口、槽位和启动规则仍以当次已确认主程序根目录下的同名文档为准。不得把主程序脚本路径当成本维护仓脚本路径。

## 构建与路径

- 仓库根目录由当前 Git 工作目录确认，禁止固定旧电脑盘符或用户名。
- 构建前解析新 worktree 的绝对路径，确认可写、未存在且不位于当前仓库源码子目录中；指定 WorktreeRoot 时必须位于其内。
- 每次发布新建本任务专用的临时 worktree，检出本次目标提交；仅以该提交的已提交内容构建，记录 HEAD、干净状态、命令及产物摘要。
- 纯资源包构建不启动主程序前后端，不制造主程序端口或槽位登记；若需要启动主程序，必须先按主程序实际规则登记并检查端口。
- 不因盘符不同而拒绝已验证的合法路径，不在失败后随机换目录继续。

## 原件与收尾

- 未提交内容、未跟踪文件和脏工作区内容不能混入发布包。
- 有未合并提交、归属不明改动或验证失败时保留 worktree 并记录阻塞，不删除或宣称交付完成。
- 发布完成且无新增提交的专用构建 worktree 应删除；若有新增提交，先融合到 int_main 并验证，再删除。
- 清理前确认工作区、进程和任务归属；不删除其他任务的 worktree、数据、登记或控制台。
- 原件、验证输入与历史证据保持；不得在旧断链 worktree 内修改 Git 元数据伪装恢复成功。

本页据本次已核实的主程序 `docs/worktree-restrictions.md` 中可移植路径、构建隔离、端口和清理边界整理，并结合本维护仓 AGENTS.md 的发布 worktree 规则。原文定位和 SHA 见本任务执行记录。
