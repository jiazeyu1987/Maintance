# 发布页面验收规则

本文件是发布页面验收的统一判定规则，适用于测试、正式及备用环境；登录账号和访问边界仍由[登录访问规则](login-access.md)与当次授权确定。它统一原“console错误非零一律阻断”和“带观察项通过”的冲突，不新增业务功能，也不自动追认历史验收结果。

## 前置门禁

- Trigger: 发布后真实登录、页面冒烟、版本确认，或准备记录页面PASS/PASS_WITH_OBSERVATIONS并进入后续发布阶段。
- Preflight check: 固定环境、releaseTag、包摘要和任务编号；列明本轮必需页面、动作、可观察预期及变更涉及的业务验收要求。确认实际授权账号和真实既有数据。Playwright在导航前监听console、pageerror、requestfailed及必需接口响应，保留完整观察窗口；事先核对只读场景可能触发的写入。
- Blocker: 登录失败、版本不符、关键页面/必需资源不可用、必需接口HTTP或业务code失败、业务错误、未经授权副作用、异常影响未知、观察窗口或必要证据缺失，均为BLOCKED。console条数本身不是故障影响判定；错误为零也不能替代必需检查。
- Verification: 对照下述决策表逐项核查真实登录、必要页面数据/动作、前后端版本与必需请求。所有异常必须有原始证据及归因；只允许满足全部观察条件的非关键外部资源失败或验证器主动拦截进入PASS_WITH_OBSERVATIONS。
- Forbidden action: 不按域名、HTTP方法、错误字符串或“以前也有”自动忽略；不清空错误数组、mock响应、跳过失败动作、增加产品入口凑验收；不将HTTP200当业务成功，不将技术登录或基础冒烟冒充完整业务E2E，不改历史失败结论。
- Evidence: 当前任务的页面验收记录、Playwright实际截图/追踪/请求证据及逐项异常表；规则变更记录为`doc/tasks/20261119-update-and-release-prod/acceptance-policy-log.md`，实现和验证记录为同目录`version-acceptance-fix.md`。

## 范围与责任

发布基础冒烟至少包含真实登录、约定关键页面可用及真实数据呈现、页面版本与候选一致、必需请求成功。变更涉及的业务验收由IntRuoyi提供可追溯证据，发布核对其版本与范围；未完成的业务验收若是本次变更的必要条件，必须阻断相应晋级。用户明确另行处理的业务任务保留未完成状态，不将其写为已通过，也不自动扩大每次发布的必测范围。

页面判定仅证明已列明范围。manifest、IMAGE_TAG、实际镜像、后端健康、迁移、来源同步和人工开放条件仍按各自发布合同独立核验。

## 判定顺序与决策表

先核绑定和必需检查，再逐条分析全部异常，最后归并结果。任一BLOCKED优先于PASS_WITH_OBSERVATIONS；没有阻断且没有观察项才为PASS。

| Given / 已有事实 | When / 判定依据 | Then / 结果 |
| --- | --- | --- |
| 真实登录、关键页面、版本、必需请求全部通过，完整观察窗口无异常 | 必需证据齐全 | PASS |
| console为0，但登录/关键数据/版本任一未验证 | 必要证据缺失 | BLOCKED |
| HTTP200但业务code失败，或必要资源/接口失败、白屏、页面异常 | 必要功能失败或业务错误 | BLOCKED |
| 非关键外部资源失败 | 逐项满足下述观察条件，且全部必需检查通过 | PASS_WITH_OBSERVATIONS |
| 已知或历史外部错误，但未证明本轮影响 | 只有历史说明或域名判断 | BLOCKED |
| 验证器为只读边界主动拦截请求 | 有事前拦截规则、请求对应证据，且证明该请求不属于本轮必需路径、没有改变已验证结果 | PASS_WITH_OBSERVATIONS |
| 主动拦截请求影响关键页面，或副作用/影响不明 | 不能证明合法且不影响必需路径 | BLOCKED |
| 未归因console/pageerror/requestfailed | 影响未知 | BLOCKED |
| 基础冒烟通过，Excel导入回归未执行 | 报告验收范围 | 只记基础冒烟结果；Excel回归保持未执行，是否阻断按事前列明的变更验收要求决定 |

非关键观察必须同时满足：

1. 原始异常未被丢弃，已关联到具体请求/资源或具体拦截规则；仅有console文本和数量不足以归因。
2. 已明确资源用途及失败原因，并说明为何不属于本轮必要功能；外部域名本身不证明非关键。
3. 本轮相关页面、数据和约定动作真实通过，证据能支持“不影响已验范围”，不是推测或历史结果。
4. 主动拦截属于事前只读保护而非为消除失败临时添加；若必要路径要求写入，应回到授权的测试租户执行相应验证，不能将拦截后的路径冒充完整路径。
5. 记录评估人、结论、未修项及责任归属。每一条异常独立判断，不设全局忽略名单。

## 执行阶段与记录

1. 执行前：列出目标、绑定包、必需检查及授权边界。推荐先读取本文件、`docs/login-access.md`和本次已提交Playwright验证脚本，核脚本的真实入口与事件监听；缺账号、数据、入口或必要脚本时Fail Fast。记录实际脚本路径/摘要、命令意图、授权账号标签及检查范围；命令与输出不得带凭据。
2. 页面执行：以项目已确认运行目录和Playwright版本实际打开页面、登录并操作，等待本轮约定动作及其必要请求完成；接口仅用于最终核验。保留观察起止时间和实际动作结果。必要动作失败即停止后续放行，保留失败证据；不要继续尝试不相关业务写入。
3. 判定：按决策表填充以下记录，对每项异常给出归因证据。发现未知/业务错误/必需资源失败即BLOCKED；不能只把status改成观察通过。
4. 后续阶段：PASS或PASS_WITH_OBSERVATIONS仅满足页面门禁，仍需其他同包发布条件通过。若BLOCKED则只阻止依赖该验收的动作；已有部署事实和原失败记录保持，不自动回滚、重发或修业务。

统一记录至少包含：

- `environment`、`releaseTag`、`packageSha256`、`jobId`、实际入口（脱敏）、脚本身份、观察起止时间、评估人。
- `checks`：逐项name、expected、actual、status、evidence；真实登录、页面/数据、版本和必需接口不能只写一个总PASS。
- `observations`：逐条id、kind（console/pageerror/requestfailed/http/business/interception）、来源origin/path、脱敏错误、对应原始证据、归因、是否必要、影响依据、disposition（blocking/nonblocking）、责任/待办。聚合数量需与原始事件相符。
- `status`：PASS、PASS_WITH_OBSERVATIONS或BLOCKED；`scope`列明已验与未验事项，`blockers`列明具体缺口，观察通过必须列出全部非阻断观察项。

私密原始证据按现有策略保存；公开记录不含密码、token、Cookie、请求正文、查询参数或个人敏感数据。重复事件可以关联同一问题，但原始计数和事件引用保持。

现有技术登录脚本只证明其明确输出的认证/配置范围，人工验收备注也不是上述页面证据的替代。本文件是执行规则，未宣称Spug已自动采集或强制验证完整记录；自动化接入须另行通过真实入口的BDD/TDD验证。
